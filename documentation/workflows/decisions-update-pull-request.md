# Update Pull Request

**File:** [`/.github/workflows/decisions-update-pull-request.yml`](../../.github/workflows/decisions-update-pull-request.yml)
**Script:** [`/.github/scripts/format-decision-for-pr.py`](../../.github/scripts/format-decision-for-pr.py)
**Trigger:** `workflow_run` after Challenger Analysis completes successfully on a `decisions/**` branch.

## Purpose

Closes the decision pipeline by surfacing the fully-populated decision content in the PR description. Reviewers see the narrative and all seven analysis sections (Context Validation through Challenger Analysis) without opening the JSON file.

## Behaviour

1. Checks out the decision branch.
2. Reads the decision JSON at `architectures/clients/<client>/<version>/decisions/<decision-id>/decision.json`.
3. Runs `format-decision-for-pr.py` to produce a markdown rendering: title, ID, status, narrative, then each analysis section (with multiple findings rendered as numbered sub-blocks).
4. Looks up the open PR for the branch via `gh pr list --head <branch>`.
5. If a PR is open, replaces its description with the formatted markdown via `gh pr edit --body-file`.
6. If no PR is open, exits with a notice (no error).

## Notes

- The workflow only runs at the end of the chain, not after every intermediate commit. This avoids churn — each upstream workflow's commit is superseded by the next, so the PR only needs updating once.
- If Challenger Analysis fails, this workflow does not run. The PR description stays at whatever `Create Pull Request` produced (stub).
- The replacement is full: any previous description content (including the stub from `Create Pull Request`) is overwritten. The footer line `_Auto-generated by the Update Pull Request workflow…_` signals the source.
- Uses the default `GITHUB_TOKEN`, with `pull-requests: write` permission set in the workflow.
- Requires the repo setting *"Allow GitHub Actions to create and approve pull requests"* — same setting `Create Pull Request` already needs.
